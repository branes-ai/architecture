# Plan: every repo's records on the site, and checked in its CI

Approved 2026-10-29 ([architecture#8](https://github.com/branes-ai/architecture/issues/8)). A1 is this plan's first PR; the others are to come.

Follows the [records-site plan](../records-site/README.md), which published the ADRs and plans of the stack repos and checked them in anatomy, racing-drone and cortex.

## Goal

1. **Every repo whose records the site collects checks them in its CI,** strict, with the `check-records` action: synapse, reflex, and the five drone repos (scout-drone, isr-drone, nano-drone, interceptor-drone, counter-uas).
2. **The repos with plans that the site doesn't list yet join it:** auto-drone, embodied-ai-architect and graphs.
3. **reflex gets a `docs/` like anatomy's and racing-drone's.** `docs/` becomes the source of the docs site, generated by a `sync-docs.mjs`. It gains `adr/`, `plan/`, `sessions/`, `assessments/` and `benchmarks/`:
   - `adr/` and `plan/` go to the architecture site;
   - `sessions/` is published nowhere;
   - `assessments/` and `benchmarks/` are published on the reflex site.

## What the survey found

Of the 41 source repos in branes-ai, these have ADRs or plans as files. The scan covered `adr/`, `adrs/`, `decisions/`, `plan/` and `plans/` folders at any depth.

| Repo | Folder | Files | Listed in `sources.yaml` | Records check in CI |
|---|---|---|---|---|
| anatomy, racing-drone, cortex | `docs/adr/`, `docs/plan/` | | yes | yes |
| synapse | `docs/plan/` | 1, with front matter | yes | no |
| reflex | none (`docs/` holds a README) | 0 | yes | no |
| scout-drone, isr-drone, nano-drone, interceptor-drone, counter-uas | none | 0 | yes | no CI at all |
| auto-drone | `docs/plans/` | 3 | no | no |
| embodied-ai-architect | `docs/plans/` | 57: 54 records, plus 3 notes in `crew-ai/` | no | no |
| graphs | `docs/plans/` | 15 | no | no |

**The three new repos:**
- **Front matter:** nearly none of their plans has it. Some have a prose status, such as "Initial Design" or "Revised".
- **Dry run:** a strict `check-records` run over the three repos found 4 errors, and none of them are links:
  - three embodied-ai-architect files have no `# ` title (two `crew-ai/` notes and `roadmap-phase-3.md`);
  - one auto-drone file starts with a byte-order mark before its title. That one is a collector bug.

**The collector:**
- **Folder names:** it takes a record's kind from its folder's name. A `plans/` folder would therefore publish its files as kind `plans`, with no status check.
- **Byte-order mark:** it doesn't strip a byte-order mark.

**reflex:**
- **Pages:** its 27 pages are written in `docs-site/src/content/docs/`.
- **Imports:** the MDX pages import the trace player and their traces by relative paths (`../../../components/...`, `../../../traces/...`). Those paths still resolve when the sync keeps the layout.
- **The animation plan:** its p0–p3 (#37–#48) lives inside the standards page `standards/animation.md`, together with its assessment and its rules.
- **Other references:** one header comment names the content path (`tools/trace/.../writer.hpp`).

## The changes

### The collector (architecture)

- **Folder names:** a folder named `plans` holds plans and one named `adrs` holds ADRs. The route keeps the folder's name (`/graphs/plans/<name>/`), so it still follows from the path.
- **Byte-order mark:** stripped before parsing.
- **The `check-records` action** gets a `folders` input. It overrides `sources.yaml` for a repo whose CI runs the check before the repo is listed.
- **Tests** cover each change.

### The check in each repo

Each repo gets the same CI job as anatomy (`Architecture records`, pinned to the architecture commit with the changes above, strict):
- **synapse and reflex:** added to `ci.yml`.
- **The five drone repos:** a new `.github/workflows/records.yml`. Each has no records yet, so the job passes at 0 records until one lands.

### auto-drone, embodied-ai-architect, graphs

One PR per repo:
- **Front matter:** each plan gets front matter. The status comes from its own text, its commit history, and the issues and PRs it names. It's `draft` where the evidence doesn't show approval.
  - Any prose `Status:` line goes, as in the stack repos.
  - A plan with a date line keeps it.
- **The PR body** has a table: plan, status, evidence. Your review of that table is the check on each inferred status.
- **Missing titles:** the files with no `# ` title get one.
- **Notes inside `plans/`:** files that aren't plans (the three `crew-ai/` notes) stay where they are, published as attachments, with no status.
- **CI:** the records job with `folders: plans`.

Then `sources.yaml` adds the three repos with `folders: [plans]`.

Out of scope: those repos' own docs sites. None publishes `docs/plans/`.

### reflex

Two PRs.

**R1, `docs/` becomes the source.**
- **Pages:** every page moves from `docs-site/src/content/docs/` to `docs/`, at the same paths.
- **Generation:** a `sync-docs.mjs` copies `docs/` into the content folder, which is then gitignored. It's anatomy's script with `REPO = 'reflex'`. It runs on `prebuild` and `predev`, so the deploy workflow, the CI docs job and local builds all generate the site.
- **Workflow triggers:** the deploy workflow's `paths` gain `docs/**`.
- **Edit links:** they point at `docs/`.
- **References:** the writer header comment, and the paths in `building-blocks.md`, follow the move.
- **No content changes.**

**R2, the new folders and their first content.**
- **`docs/adr/`, `docs/sessions/`, `docs/benchmarks/`:** a README each, saying what goes in the folder and how files are named. The ADR README points at cortex's template.
- **`docs/plan/animation/README.md`:** the plan part of `standards/animation.md`, that is, its infrastructure and order of work. Front matter `in-progress`, because p3 parts 1–3 merged (#43, #45, #48) and the plan names more.
- **`docs/assessments/animation.md`:** the page's "Assessment" section.
- **`standards/animation.md`:** keeps the rules (the four pages, provenance, the SITL boundary) and links to the plan and the assessment.
- **The sync:** skips `adr/`, `plan/` and `sessions/`. A link from a user page to a record goes to its page on the architecture site, as in anatomy.
- **The site:** `assessments/` and `benchmarks/` get sidebar groups, and so does a "Plans and decisions" link.
- **CI:** the records job.

## Acceptance (stated before any test is run)

1. **Every repo in `sources.yaml` runs the records check in its CI,** strict, and it passes on its default branch: 14 repos, including architecture's own.
2. **The site lists every `.md` file** under the listed folders of the 14 repos, checked by `check-coverage.sh` against a `find` of the clones. Today that's 72 more files from the three new repos (54 + 3 + 15) and 2 more from reflex.
3. **The strict build is green, and no record shows unknown.**
4. **Every status inferred in E1–E3 has its evidence** in the PR's table.
5. **R1 changes no published page.** The reflex site built after R1 has the same 27 routes as before. Each page's HTML is identical except for the edit link.
6. **After R2:**
   - the reflex site has no page from `adr/`, `plan/` or `sessions/`;
   - `assessments/animation` is published there;
   - the animation plan is on the architecture site, with status `in-progress`;
   - every link from a reflex page to a record reaches the architecture site.
7. **CI is green, and commitlint is clean,** in every repo touched.

## Risks

- **An inferred status can be wrong.** The evidence table makes each one reviewable, and changing a status later is a one-line edit.
- **Repos outside the stack (embodied-ai-architect, graphs, auto-drone) have their own maintainers.** Their PRs touch only front matter, four titles and one CI job.
- **R1 moves 27 files.** Acceptance 5 checks that the published site is unchanged.
